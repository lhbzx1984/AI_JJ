NVIDIA 提供了从底层驱动到上层应用的完整 AI 软件堆栈，是 AI 开发和部署的基础。

  • RAPIDS — 数据科学 GPU 加速库（cuDF 数据处理、cuML 机器学习、cuGraph 图分析）
  • Triton Inference Server — 开源推理服务软件，支持多种框架模型部署

1.2 比较和对比训练和推理架构的要求和注意事项 ▶

训练（Training）和推理（Inference）是 AI 生命周期的两个核心阶段，对硬件和软件的要求截然不同。

训练 vs 推理对比

维度训练 (Training)推理 (Inference)
目标从数据中学习模型参数使用训练好的模型进行预测
计算过程前向 + 反向传播（梯度计算）仅前向传播
计算量极高（需大量迭代）相对较低
内存需求大（需存储模型参数、梯度、优化器状态）较小（仅存储模型参数）
精度要求通常需要 FP32/FP16/混合精度可降低至 FP16/INT8/INT4
硬件DGX 系统、大型 GPU 集群单 GPU、边缘设备、推理服务器
关键指标吞吐量（样本/秒）、收敛速度延迟、吞吐量
网络需求高带宽（InfiniBand）、多节点通信中等（服务请求）
软件PyTorch、TensorFlow、CUDA、cuDNNTensorRT、Triton、ONNX Runtime
并行策略数据并行、模型并行、流水线并行批处理并行

训练架构关键考虑

  • 多节点通信：NCCL 库处理多 GPU 通信，需要 InfiniBand 或 NVLink/NVSwitch 高速互联
  • 内存容量：大模型训练需要大量 GPU 显存（如 H100 80GB）
  • 混合精度训练：使用 FP16/BF16 加速，同时保持 FP32 精度的主权重
  • 检查点（Checkpoint）：定期保存模型状态，支持故障恢复
  • 分布式训练：数据并行、模型并行（张量并行、流水线并行）

推理架构关键考虑

  • 延迟优化：减少推理时间，使用 TensorRT 优化模型图
  • 量化：FP32 → FP16/INT8 降低计算和内存需求
  • 批处理：动态批处理提高吞吐量
  • 模型部署：Triton Inference Server 支持多框架模型服务
  • 边缘推理：在 Jetson 等边缘设备上部署轻量化模型
考试重点：训练需要更多计算和内存资源（反向传播），推理更关注延迟和吞吐量优化。训练用 DGX/集群，推理用 TensorRT/Triton 优化。
训练推理反向传播TensorRT量化混合精度NCCL动态批处理
1.3 区分 AI、机器学习和深度学习的概念 ▶

AI、ML 和 DL 是嵌套关系：DL ⊂ ML ⊂ AI。

人工智能 (AI)

  • 最广泛的概念：使机器表现出类人智能的任何技术
  • 包含：规则系统、专家系统、搜索算法、机器学习等
  • 不限于学习方法，也包含规则驱动的方法

机器学习 (ML)

  • AI 的子集：通过数据学习模式，而非显式编程
  • 监督学习：有标签数据（分类、回归）
  • 无监督学习：无标签数据（聚类、降维）
  • 强化学习：通过奖励信号学习（游戏 AI、机器人）
  • 典型算法：线性回归、决策树、SVM、K-Means、随机森林

深度学习 (DL)

  • ML 的子集：使用多层神经网络进行学习
  • CNN：卷积神经网络，擅长图像处理
  • RNN/LSTM：循环神经网络，擅长序列数据
  • Transformer：注意力机制，大语言模型基础（GPT、BERT）
  • GAN：生成对抗网络，用于生成数据
  • 需要大量数据和 GPU 计算资源
维度AIMLDL
范围最广中等最窄
方法规则+学习统计学习神经网络
数据需求不定中等大量
计算需求低中等高（GPU）
可解释性高中低（黑箱）
特征工程人工需要自动学习
考试重点：DL 是 ML 的子集，ML 是 AI 的子集。DL 使用深度神经网络，自动特征学习，需要大量数据和 GPU。传统 ML 需要人工特征工程。
1.4 解释促成近期 AI 快速改进和采用的因素 ▶

近年来 AI 快速发展的核心驱动因素：

关键因素

  • GPU 加速计算：NVIDIA GPU 提供大规模并行计算能力，使训练大型神经网络成为可能。GPU 计算性能指数级增长（从 Kepler 到 Hopper 架构）
  • 大数据的可用性：互联网产生海量数据（文本、图像、视频），为模型训练提供了丰富素材
  • 算法突破：Transformer 架构（2017）开创了大语言模型时代；GAN、扩散模型推动生成 AI 发展
  • 框架民主化：PyTorch、TensorFlow 等开源框架降低了 AI 开发门槛
  • 云计算普及：AWS、Azure、GCP 提供按需 GPU 资源，无需自建数据中心
  • 迁移学习和预训练模型：BERT、GPT 等基础模型可微调适配各种任务
  • 开源生态系统：Hugging Face、NGC 容器等让模型共享和部署更容易
  • 专用硬件：TPU、NPU、推理专用芯片不断涌现
  • 软件栈成熟：CUDA、cuDNN、TensorRT 等优化库持续提升效率
考试重点：GPU 并行计算是 AI 突破的核心驱动力。大数据 + 算法突破（Transformer）+ GPU 算力 + 开源框架共同推动了 AI 快速发展。

1.8 比较和对比 GPU 和 CPU 架构 ▶

CPU 和 GPU 设计理念不同，适用于不同类型的计算任务。

维度CPUGPU
核心数量少量强大核心（4-64）大量简单核心（数千-万）
设计目标低延迟、通用计算高吞吐量、并行计算
计算模式SIMD/MIMD 混合SIMT（单指令多线程）
缓存大容量多级缓存（L1/L2/L3）小缓存，更多晶体管用于计算
内存带宽较低（DDR）极高（HBM）
控制逻辑复杂（分支预测、乱序执行）简单
擅长任务串行、控制流、I/O、操作系统并行、矩阵运算、图像处理、深度学习
延迟低较高（但有高吞吐）
能效（FLOPS/W）较低高（对并行任务）

为什么 GPU 适合深度学习

  • 深度学习核心运算是矩阵乘法（GEMM），GPU 的 SIMT 架构天然适合
  • GPU 提供数千个并行计算核心，可同时处理大量计算
  • HBM 高带宽内存（H100: 3.35 TB/s）满足大模型数据吞吐需求
  • Tensor Core 专门加速矩阵运算（FP16/INT8/FP8）
  • CUDA 生态系统提供完善的编程模型

NVIDIA GPU 架构演进

  • Kepler (2012) → Maxwell (2014) → Pascal (2016)：早期 GPU 计算
  • Volta (2017)：引入 Tensor Core，AI 计算革命
  • Turing (2018) → Ampere (2020)：Tensor Core 增强，多实例 GPU (MIG)
  • Hopper (2022)：H100，Transformer Engine，FP8 精度
  • Blackwell (2024)：B200，第二代 Transformer Engine
考试重点：CPU 擅长串行低延迟任务，GPU 擅长并行高吞吐任务。GPU 的 Tensor Core 和 HBM 内存是加速深度学习的关键。CPU 有少量复杂核心+大缓存，GPU 有大量简单核心+高带宽。

2.1 理解数据挖掘、数据可视化和从大型数据集提取见解的过程 ▶

数据挖掘 (Data Mining)

从大型数据集中发现模式、关联和异常的过程，是知识发现 (KDD) 的核心步骤。

  • 分类 (Classification)：预测离散标签（垃圾邮件检测）
  • 回归 (Regression)：预测连续值（房价预测）
  • 聚类 (Clustering)：发现自然分组（客户分群）
  • 关联规则 (Association Rules)：发现频繁项集（购物篮分析）
  • 异常检测 (Anomaly Detection)：识别异常模式（欺诈检测）

数据可视化 (Data Visualization)

  • 将数据转化为图形以辅助理解和决策
  • 常用图表：折线图（趋势）、柱状图（比较）、散点图（关系）、热力图（密度）、箱线图（分布）
  • GPU 加速可视化：RAPIDS cuDF 可处理超大规模数据集

数据提取见解的流程

步骤说明
1. 数据采集从数据库、API、传感器、日志等获取原始数据
2. 数据清洗处理缺失值、异常值、重复数据
3. 数据转换标准化、归一化、编码、特征提取
4. 探索性分析统计描述、可视化、模式发现
5. 建模分析应用 ML/DL 算法挖掘深层模式
6. 结果解释将分析结果转化为业务见解
7. 可视化展示通过仪表板、报告传达发现
考试重点：数据挖掘是 KDD 的核心步骤。ETL（提取-转换-加载）是数据准备流程。GPU 加速（RAPIDS）可以大幅加速数据挖掘和可视化。

指标公式/定义适用场景

回归指标

  • R² (决定系数 / 解释方差比例)：模型解释目标变量方差的比例，0-1 之间
  • RMSE (均方根误差)：MSE 的平方根，与目标值同量纲
  • 调整 R²：考虑特征数量，防止过拟合误导

过拟合与欠拟合

  • 过拟合：训练表现好，测试表现差（模型太复杂）→ 增加数据、正则化、Dropout
  • 欠拟合：训练和测试都表现差（模型太简单）→ 增加模型复杂度
  • 偏差-方差权衡：高偏差=欠拟合，高方差=过拟合
考试重点：理解各指标含义和适用场景。精确率 vs 召回率的取舍（如医疗诊断重召回率）。R² 衡量解释方差比例。混淆矩阵是分类评估基础。
2.3 在高级团队成员的监督下进行数据分析 ▶

探索性数据分析 (EDA)

  • 统计描述：均值、中位数、标准差、四分位数
  • 分布分析：直方图、密度图、QQ 图
  • 相关性分析：皮尔逊/斯皮尔曼相关系数、相关矩阵热力图
  • 分组分析：按类别分组的统计比较

假设检验

  • t 检验：比较两组均值差异
  • 卡方检验：分类变量独立性检验
  • ANOVA：多组均值比较
  • p 值：统计显著性判断（通常 p<0.05）

特征工程

  • 特征提取：从原始数据提取有用特征
  • 特征转换：标准化、归一化、对数变换
  • 特征编码：独热编码、标签编码
  • 特征选择：过滤法、包装法、嵌入法
  • 降维：PCA（主成分分析）、t-SNE、UMAP
考试重点：EDA 是数据分析的第一步。特征工程是 ML 流程的关键环节。标准化/归一化确保特征在同一尺度。PCA 用于降维。

2.5 识别关系和趋势或可能影响研究结果的因素 ▶

关系识别方法

  • 相关性分析：皮尔逊（线性）、斯皮尔曼（单调）相关系数，范围 -1 到 1
  • 散点图分析：直观观察两个变量关系
  • 交叉表分析：两个分类变量的关系
  • 特征重要性：识别对模型影响最大的特征

趋势识别

  • 时间序列分析：移动平均、指数平滑、ARIMA
  • 季节性分解：趋势、季节性、残差
  • 变化点检测：识别数据分布突变点

影响研究结果的因素

因素影响应对
数据质量缺失、噪声、错误影响分析数据清洗、验证
样本量小样本导致统计不显著增加样本、功效分析
偏差 (Bias)选择偏差、测量偏差随机采样、双盲设计
混杂变量第三方变量影响关系控制变量、随机化
过拟合模型记忆训练数据交叉验证、正则化
数据泄露测试信息泄露到训练严格分离训练/测试
样本不平衡少数类被忽视重采样、类别权重
考试重点：相关性不代表因果关系。混杂变量可能产生虚假相关。数据泄露是 ML 中常见错误。样本不平衡需要特殊处理（SMOTE、类别权重）。

D3AI 运营（22%）

涵盖 AI 数据中心管理监控、集群编排与作业调度、GPU 监控标准及虚拟化加速基础设施。

3.1 说明 AI 数据中心管理和监控要点 ▶

带外管理 (Out-of-Band Management)

  • BMC (Baseboard Management Controller)：服务器主板上的独立管理控制器，即使服务器关机也可远程管理
  • IPMI：智能平台管理接口，BMC 通信标准
  • 用途：远程开关机、硬件监控、系统日志、固件更新
  • 优势：不依赖操作系统，独立网络通道

NVIDIA 管理工具

工具类型功能
NVIDIA DCGMGPU 管理数据中心 GPU 管理器，监控 GPU 健康、性能、使用率
NVIDIA Base Command集群管理DGX 集群的管理软件，作业调度和资源分配
nvidia-smi命令行GPU 状态查看工具（利用率、温度、显存）
BMC硬件管理服务器带外管理，独立于 OS

关键监控指标

  • GPU 利用率：计算使用率，低利用率可能表示瓶颈
  • 显存使用率：GPU 内存占用，防止 OOM
  • 温度：GPU 温度监控，过热降频
  • 功耗：功耗墙限制，影响计算性能
  • 网络 I/O：InfiniBand/Ethernet 带宽利用率
  • 存储 I/O：读写吞吐量和延迟

数据中心环境监控

  • 制冷：液冷/风冷，高密度 GPU 服务器散热
  • 电力：功耗、PUE（数据中心能效）
  • 物理安全：门禁、视频监控
考试重点：BMC 提供带外管理（独立于 OS）。DCGM 是 NVIDIA GPU 专用监控工具。Base Command 管理 DGX 集群。nvidia-smi 是基础命令行工具。
3.2 说明 AI 集群编排和作业调度要点 ▶

容器化 (Containerization)

  • Docker：轻量级容器技术，打包应用及依赖
  • NGC 容器：NVIDIA 提供的 GPU 优化 AI 容器镜像
  • 优势：环境一致性、快速部署、资源隔离
  • Kubernetes (K8s)：容器编排标准，管理大规模容器集群
  • NVIDIA GPU Operator：Kubernetes 中自动管理 GPU 资源的组件

集群编排工具

工具类型特点
Kubernetes容器编排自动部署、扩缩容、服务发现；GPU Operator 管理 GPU
Slurm作业调度HPC 领域标准，队列管理，多用户共享
NVIDIA Base CommandDGX 管理NVIDIA 专用 DGX 集群管理和作业调度
KubeflowML 平台基于 K8s 的 ML 工作流编排

作业调度策略

  • FIFO (先到先服务)：简单但可能导致资源碎片
  • 公平共享 (Fair Share)：确保各用户/团队公平使用资源
  • 优先级调度：高优先级作业优先
  • 回填 (Backfill)：利用碎片时间运行小作业
  • 独占 vs 共享：作业独占节点 vs 多作业共享

MLOps 要点

  • CI/CD 流水线：自动化训练、测试、部署
  • 模型版本管理：MLflow、DVC 追踪模型版本
  • 模型监控：性能漂移、数据漂移检测
  • 实验追踪：超参数和指标记录
考试重点：Kubernetes + GPU Operator 管理容器化 GPU 工作负载。Slurm 是 HPC 作业调度标准。Docker/NGC 容器确保环境一致性。理解 FIFO、公平共享等调度策略。
3.3 阐明与监控 GPU 相关的关键措施和标准 ▶

GPU 监控工具

工具层级功能
nvidia-smi命令行实时 GPU 状态（利用率、显存、温度、进程）

核心监控指标

指标说明关注点
GPU 利用率SM 占用率低利用率 → 可能瓶颈在数据加载或 CPU
显存使用GPU 内存占用接近 100% → OOM 风险

GPU 利用率低的原因

  • 数据加载瓶颈（CPU/IO 限制）→ 使用 DALI 加速数据加载
  • 批量太小 → 增大 batch size
  • CPU 预处理瓶颈 → GPU 加速预处理
  • 网络通信瓶颈 → 优化 NVLink/InfiniBand 配置
  • 不合理的模型架构 → 减少 CPU 控制逻辑

考试重点：DCGM 是数据中心 GPU 管理标准。nvidia-smi 是基础命令行工具。低 GPU 利用率的常见原因（数据加载瓶颈、小 batch size）。Xid 错误表示硬件问题。
3.4 确定虚拟化加速基础设施的关键注意事项 ▶

GPU 虚拟化技术

技术说明隔离级别
NVIDIA vGPU软件级 GPU 虚拟化，多个 VM 共享物理 GPU软件隔离
MIG (Multi-Instance GPU)硬件级 GPU 分区，A100/H100 支持硬件隔离（最强）
vCUDAAPI 级虚拟化API 隔离
PCIe PassthroughGPU 直通给单个 VM物理隔离

MIG (Multi-Instance GPU)

  • 将单个物理 GPU 在硬件层面分区为多个独立实例
  • 每个实例有独立的计算和内存资源，硬件级隔离
  • 支持 A100 (7 个实例) 和 H100
  • 适用于多用户共享 GPU、推理服务隔离
  • 优势：故障隔离、性能可预测、安全隔离

vGPU 关键考虑

  • 资源分配：显存和计算力的合理分配
  • 性能开销：虚拟化引入的延迟和开销
  • 许可：NVIDIA vGPU 需要软件许可
  • 兼容性：与 VMware vSphere 等虚拟化平台集成
  • 多租户：多用户/多应用安全隔离
  • 动态调度：根据需求动态调整 GPU 资源

容器 vs 虚拟机

维度容器 (Docker/K8s)虚拟机 (VM)
隔离进程级硬件级（更强）
开销低较高
启动速度秒级分钟级
GPU 共享GPU Operator + 时间片vGPU / MIG
考试重点：MIG 提供硬件级 GPU 分区隔离。vGPU 是软件级虚拟化。PCIe Passthrough 将整个 GPU 直通给一个 VM。理解各虚拟化方案的隔离级别和适用场景。
